# Корпоративный чат — этап 5

Консольный TCP-чат поддерживает несколько клиентов, JSON-протокол, регистрацию,
личные сообщения и постоянные каналы. Учётные записи, каналы и их участники
хранятся в SQLite и остаются доступны после перезапуска сервера.

Требуется Python 3.9 или новее. Сторонние библиотеки не нужны.

## Возможности

- регистрация и вход по имени и паролю;
- повторная попытка входа в том же соединении после неверного пароля;
- обязательное подтверждение пароля при регистрации;
- SQLite-база пользователей `data/chat.db`;
- `scrypt`-хеширование паролей с индивидуальной случайной солью;
- регистронезависимые имена пользователей;
- запрет команд чата до успешной аутентификации;
- запрет одновременного входа в одну учётную запись;
- общий чат для нескольких пользователей;
- список пользователей онлайн;
- личные сообщения между пользователями;
- единый список общих, личных и канальных чатов;
- выбор активного чата по номеру;
- создание постоянных каналов;
- вступление и выход из каналов;
- доставка сообщений только участникам канала;
- JSON-пакеты, `request_id`, подтверждения и коды ошибок;
- проверка типов и допустимых размеров входных данных.

## Запуск сервера

Из корневой папки проекта:

```powershell
python -m server.server
```

Другой путь к базе можно указать параметром:

```powershell
python -m server.server --database D:\chat-data\corporate.db
```

## Регистрация

В отдельном терминале:

```powershell
python -m client.client register
```

Клиент сначала запросит имя пользователя. Сервер сразу проверит, свободно ли
оно, и только после успешной проверки клиент дважды скрыто запросит пароль.
Допустимая длина пароля — от 8 до 128 символов. После регистрации пользователь
сразу входит в чат. Если пароль не пройдёт проверку сервера, его можно ввести
заново без переподключения.

Имя должно содержать от 3 до 32 букв, цифр или символов `_`, `.`, `-`.

## Повторный вход

```powershell
python -m client.client login
```

Клиент отдельно запросит имя, дождётся ответа сервера, а затем запросит пароль.
При неверном пароле клиент предложит повторный ввод, сохранив текущее
TCP-соединение с сервером. Имя пользователя не передаётся в команде запуска.

Для подключения к серверу на другой машине сетевые параметры указываются перед
командой `login` или `register`:

```powershell
python -m client.client --host 192.168.1.10 --port 8888 login
```

Сервер в локальной сети запускается так:

```powershell
python -m server.server --host 0.0.0.0 --port 8888
```

Команда `/exit` отключает клиента, `Ctrl+C` останавливает приложение.

## Команды чата

После входа клиент автоматически показывает пронумерованный список:

```text
Ваши чаты:
  1. Общий чат (общий)
  2. anna (личный)
  3. developers (канал)
```

Все зарегистрированные пользователи автоматически участвуют в общем чате. Для
работы с интерфейсом используются команды:

```text
/open N                    открыть чат по номеру
/create NAME               создать и сразу открыть канал
/refresh                   обновить список чатов
/back                      закрыть текущий чат и вернуться к списку
/leave                     выйти из открытого канала
/help                      показать справку
/exit                      выйти
```

После `/open N` любой обычный текст отправляется в выбранный чат. Поэтому для
общих, личных и канальных сообщений больше не нужно помнить разные команды:

```text
/open 1
Привет всем!
/back
/open 2
Это уже личное сообщение.
```

Название канала должно содержать от 3 до 32 букв, цифр, символов `_` или `-`.
Создатель автоматически становится участником и открывает созданный канал. При
открытии доступного чужого канала клиент автоматически вступает в него.
Пользователь вне канала не получает его сообщения.

## Пакеты аутентификации

Первый шаг регистрации или входа — проверка имени:

```json
{"type":"auth_username","action":"register","request_id":"auth-1","username":"ivan"}
```

После подтверждения имени клиент отправляет пароль:

```json
{"type":"auth_password","request_id":"auth-2","password":"secret123"}
```

Успешный ответ:

```json
{"type":"response","ok":true,"action":"login","request_id":"auth-2","username":"ivan"}
```

В базе пароль в открытом виде не сохраняется. Текущая версия протокола ещё не
использует TLS, поэтому запускать её следует только в доверенной локальной сети.
Перед открытием сервера в интернет необходимо добавить шифрование соединения.
